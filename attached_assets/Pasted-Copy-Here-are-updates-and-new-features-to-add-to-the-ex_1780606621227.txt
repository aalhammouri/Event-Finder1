UPDATE 1 — FIX CONTENT EXTRACTION (critical)
══════════════════════════════════════════
The current approach sends raw document.body.innerText to the AI. This is why extraction quality is poor — the AI receives nav menus, breadcrumbs, cookie banners, footers, and sidebar junk mixed with actual content, producing "Unnamed event" and empty fields.
REPLACE innerText extraction with this:
a) Install @mozilla/readability and jsdom. After Puppeteer loads a page, get the full HTML, run Readability on it. This isolates the main content and strips boilerplate. Convert to clean text that preserves headings, links with URLs, lists, tables, and paragraph structure. If Readability fails, fall back to the page's <main> or <article> element, never full body.
b) Take a FULL-PAGE SCREENSHOT with Puppeteer on every page that triggers AI processing. Many orgs post events as flyer images, not text. The screenshot captures everything a human sees. The AI vision model reads dates, venues, prices, and dress codes baked into flyer graphics.
c) Extract all images from the page that are at least 200x200 pixels and in the main content area. Get each image's absolute URL and alt text.
d) Separately extract footer HTML and /contact page content through Readability for business info (org name, address, phone, email, hours).
e) Send ALL of the above to the AI in ONE call with labeled sections:
"""
PAGE URL: [exact URL]
MAIN CONTENT:
[Readability-cleaned text with links preserved]
IMAGES FOUND ON PAGE:
[List of image URLs with alt text]
BUSINESS INFO SOURCE (footer + contact page):
[Footer text + contact page cleaned text]
"""
Plus attach the screenshot and any flyer-sized images as vision inputs.

UPDATE 2 — THREE-TRIGGER SYSTEM FOR AI CALLS
══════════════════════════════════════════
Currently the keyword gate is the only trigger. Add two more. The AI runs when ANY of these is true:
a) Page text contains at least one search keyword (existing behavior), OR
b) Page URL path contains an event word: /event, /gala, /auction, /fundraiser, /calendar, /benefit, /banquet, OR
c) Page has thin text (under 200 characters visible) BUT contains at least one image larger than 300x300 pixels — this catches pages that are just a flyer/poster with no surrounding text.
If NONE fire, skip the page. No AI call, no credits spent.
OVERRIDE RULE: If page text contains "silent auction", ALWAYS send to AI regardless of any avoid keywords. Silent auctions must never be skipped.

UPDATE 3 — SKIP PAST/ARCHIVE PAGES
══════════════════════════════════════════
Before sending any page to the AI, check if the page URL or heading text contains: "past", "archive", "previous", "recap", "gallery", "highlights", "2020", "2021", "2022", "2023", "2024". If yes, skip that page entirely.
Also update the AI extraction prompt: "ONLY extract events with dates in the FUTURE. If the event date is clearly in the past, return event_found: false."

UPDATE 4 — STRICTER AI EXTRACTION PROMPT
══════════════════════════════════════════
Update the prompt sent to the AI:
"You MUST populate every field you can find. Do NOT return 'Unnamed event' — if you cannot find an explicit event name, use the page title or the first heading on the page. For event_name, NEVER return null or empty string.
Required fields — try hard before returning null:

event_name (use page title if nothing else)
event_date (look in text AND in images/screenshots)
venue name and address
organization name (check footer, header logo alt text, about page)
at least one contact method (email or phone)

If a field genuinely does not exist anywhere on the page or screenshot, return null — but exhaust all sources first."
