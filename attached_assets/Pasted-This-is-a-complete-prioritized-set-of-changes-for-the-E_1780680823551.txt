╔══════════════════════════════════════════╗
║  SECTION 1 — CRITICAL BUG FIXES (do first) ║
╚══════════════════════════════════════════╝
BUG 1 — Event status is always "NEW" (no diff logic):
Every event is inserted with status "NEW" because there's no comparison
against previous runs. Fix: after extracting events for a site but BEFORE
inserting, query the most recent PREVIOUS completed run for the same
url_list. For each new event, match against the previous run by event_name
(case-insensitive) + org_name:
No match → status = "NEW"
Match, but a key field changed (event_date, event_venue, event_address,
ticket_price, table_price, auction_type, formality, contact_email,
contact_phone, rsvp_link) → status = "UPDATED"
Match, nothing changed → status = "UNCHANGED"
This is what makes the weekly email digest useful (new/changed only).
BUG 2 — Hardcoded tier thresholds in scorer.ts:
getTier() uses hardcoded { tierA: 70, tierB: 45 } instead of the
config.tierThresholds passed in. Wire getTier() to read the thresholds
from config so admin changes to tier cutoffs actually take effect.
BUG 3 — Scheduler ignores database settings:
The cron is hardcoded to "0 6 * * 1". The scheduleDays, scheduleTime,
scheduleFrequency, and scheduleTimezone fields saved by the Automation UI
are stored but never read. Fix:
a) Add scheduleFrequency (text, default "weekly": daily/weekly/biweekly/
monthly) and scheduleMonthDay (integer, nullable) columns to
admin_settings if missing.
b) On server start, build the cron expression dynamically from the DB
settings.
c) When PATCH /admin/settings updates the schedule, destroy and recreate
the cron job so changes take effect WITHOUT a server restart.
ALSO FIX (moderate):
hidePast query param: Zod's coerce.boolean treats "false" as true.
Read req.query.hidePast === "false" directly (or fix coercion properly).
Remove the xlsx package from package.json — it's imported nowhere.
The /results and /runs pages duplicate nearly identical run-card UI.
Make /results = run list → click to view that run's events table;
make /runs = the history page with archive/delete/re-run actions.
Don't duplicate.

║  SECTION 3 — CRAWL OVERHAUL (completeness) ║
╚══════════════════════════════════════════╝
GOAL: every page of every site must be discovered and checked — never
silently skipped. This is the top priority.
3A. SWITCH TO FIRECRAWL /crawl WITH COMPLETENESS SETTINGS
Replace the custom per-page BFS with Firecrawl's /crawl endpoint:
crawlEntireDomain: true   // CRITICAL: default false skips sibling
// sections like /events, /gala, /blog
allowSubdomains: true     // catch give.org, events.org subdomains
sitemap: "include"
limit: 100                // per-site cap (raise if coverage shows sites
// hitting it)
maxDiscoveryDepth: 5      // generous, NOT shallow
scrapeOptions: { formats: ["markdown","links"], onlyMainContent: false,
waitFor: 3000 }
excludePaths: ["/wp-json","/wp-admin","/cart","/checkout","/login",
"/account","\.(pdf|jpg|png|gif|css|js|zip)$"]
Use a webhook to receive each finished page and write it to the DB
immediately (Replit has only 2 GiB RAM — don't hold everything in memory).
NOTE: onlyMainContent:false is required here so navigation links aren't
stripped (stripping them causes missed pages).
3B. CAPTURE CRAWL ERRORS
Firecrawl's success result EXCLUDES failed pages. After each crawl, call
the crawl-errors endpoint and record every failed/blocked/timed-out URL.
A crawl with unhandled errors is NOT complete.
3C. COVERAGE RECONCILIATION (prove completeness)
For each site, gather URLs from THREE sources and reconcile:
robots.txt — parse every "Sitemap:" line (sitemaps often aren't at
/sitemap.xml)
sitemaps — fetch each; if it's a <sitemapindex>, recursively resolve
all child sitemaps; also probe /sitemap.xml, /sitemap_index.xml
Firecrawl crawl — URLs actually discovered + crawled
Compute per site: pages_discovered (union), pages_crawled, pages_missed
(discovered but not crawled). If pages_missed > 0, flag the site INCOMPLETE
and queue the missed URLs for a direct /scrape retry.
3D. PAGINATION
Follow rel="next", numbered pagination (?page=2, /events/page/2), and
"Load More"/infinite scroll (use a browser action to click before capture,
or scrape numbered pages directly).
3E. LOW-CONFIDENCE FALLBACK
Keep got+cheerio only as a last resort. cheerio can't see JS-rendered
content, so mark any fallback page low_confidence = true and queue a
rendered retry. Never treat a fallback page as a complete read.
3F. KEYWORD FILTER TUNED FOR RECALL (before AI)
Run keyword detection on cleaned markdown to decide which pages get AI
extraction. Tune for RECALL — a wasted cheap call is fine, a missed event
is not. Broad dictionary with stems/synonyms: silent/live/online/virtual
auction, gala, raffle, drawing, 50/50, benefit dinner, fundrais*, charity,
"save the date", tickets, sponsorship, RSVP, "table of", paddle raise,
"in-kind", "gift certificate", honoree, luncheon + date regex + price
regex. Keep the "silent auction" override (always extract). Pages with
zero signal are skipped.
3G. STRICT STRUCTURED OUTPUTS
Keep using your own OpenAI extraction (do NOT switch to Firecrawl's JSON
extract — it costs ~5x). Upgrade the call to use Structured Outputs:
response_format type "json_schema", strict: true, additionalProperties:
false on every object. This guarantees valid JSON for the CRM fields.
Since strict mode doesn't enforce string patterns, validate emails/phones/
dates in code after parsing; reject unparseable dates (don't guess). Add
to the prompt: "If a field is not present, return null. Do NOT infer or
fabricate."
3H. VISION / FLYERS
Only run vision when the page passed the keyword filter AND has a candidate
flyer image. Select flyers by large dimensions (>400px), poster aspect
ratio, filename/alt-text signals (flyer, gala, auction, event, year, date),
and position in event-content. Exclude logos/icons/SVGs. For mostly-flyer
pages, send one full-page screenshot. Keep gpt-4o for vision (do NOT use
gpt-4o-mini for images — it uses ~33x the image tokens). Merge image data
into the same schema (text wins, image fills gaps); dedupe by event name +
date + venue; store provenance.
3I. COVERAGE REPORTING & MONITORING
Add per-run metrics (on crawl_runs or a run_coverage table): sites_total,
sites_complete, sites_incomplete, pages_discovered, pages_crawled,
pages_missed, pages_keyword_matched, pages_sent_to_ai, events_extracted,
vision_calls, fetch_errors, fallback_pages. On the Run Detail page, show a
"Crawl Coverage" panel highlighting any INCOMPLETE site in red, with a
drill-down to the exact missed URLs and why. After scheduled runs, flag in
the digest any site whose page/event count dropped sharply vs last run, or
any run with pages_missed > 0.
3J. DIFF CRAWLING + DEDUP (efficiency, don't sacrifice completeness)
Store a content hash of each page's cleaned markdown. On later runs, still
CRAWL every page (to find new ones) but only send NEW or CHANGED pages to
AI extraction (unchanged pages keep their prior event). Dedupe events on
normalized name + date + org/venue; keep the most complete record.
