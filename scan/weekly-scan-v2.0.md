Weekly Charity Event Scan — v2.0 (Dynamics-native, 2026-10-14)

CHANGE LOG FOR THIS VERSION
- Airtable is retired. Every read and write that v1.6 made to Airtable now targets Dynamics 365 (Dataverse org orgcad402f2) through the Microsoft_Dataverse connector. No Airtable connector is attached to this run; do not look for one.
- Organizations → table cr93c_scansource. Events → table lead. Missed Events and Screened Out → table cr93c_scanfinding (cr93c_finding_type 1 = Missed Event, 2 = Screened Out).
- The scoring formulas that lived in Airtable are computed by this run and written to lead_event_score; the routing that Pipeline Status used to do is written to lead_package_status.
- New terminal state for evidence that exists only on Facebook (Step 4 and 7A): such rows are never requeued.
- All other rules of v1.6 (Steps 3A, 5A, 7A, 9, revisit queue, concurrency guard, report) are unchanged in substance.

TOOLS
Use mcp__Microsoft_Dataverse__read_query for reads (TOP ≤ 500, no subqueries), create_record and update_record with "items"/"records" batches of 25 for writes, and describe when a column name is uncertain. Choice columns take numeric values. Dates are sent as "YYYY-MM-DDT12:00:00Z". Never send an empty string; omit the column instead.
Use the Firecrawl connector for crawling websites, the Apify connector for public Facebook pages and events (Step 4), the Gmail connector for the report. WebFetch may be used for ProPublica JSON and the IRS extract only.

SCORING (computed by this run, replaces the Airtable formulas; write the total to lead_event_score and the breakdown to description)
- Auction (max 40): if all four auction fields are No → 0. Otherwise min(40, silent Yes 15 + raffle Yes 12 + live Yes 10 + online Yes 10 + (live Yes and silent Unclear) 8 + prior-year auction Yes 8 + "auction" in event name 5 + "gala" in event name 5).
- Reach (max 30): min(30, complete mailing address 10 + named event contact 5 + contact is Employee 3 + contact title contains director/executive/development/advancement/chief/president/founder 4 + direct e-mail 4 + direct phone 2 + second contact 2).
- Timing (max 15): days until event < 7 → 0; ≤ 20 → 5; ≤ 120 → 15; ≤ 210 → 10; else 5; no date → 0.
- Verification (max 15): min(15, Candid match 6 + address from the organization website 5 + website and Candid addresses agree 4).
- Route (lead_package_status): auction score 0 → do not create a lead (Step 7A). Auction ≥ 20 and complete mailing address → Awaiting Review 714000000. Auction ≥ 20 without a mailable address → On Hold 714000006 with "Need address" or "Email track" as the first line of description. Auction 10–19 → On Hold with "Research". Auction < 10 → On Hold with "Hold".
- Excluded: PTA (case-sensitive), "elementary", "preschool" in the organization or event name → Screened Out reason 5. Sensitive: israel, palestin, political, republican, democrat, reproductive, planned parenthood, pro-life, pro-choice → Screened Out reason 6. Neither ever becomes a lead.

PHASE 0 — Hygiene and setup
0A. URL artifact assertion. SELECT cr93c_scansourceid, cr93c_name, cr93c_website_url FROM cr93c_scansource WHERE cr93c_website_url LIKE '%://http%'. Expected 0. If any appear, report the ids and skip those rows this run; do not repair mid-run.
0B. Unusable rows. Where cr93c_name has no dot AND cr93c_website_url does not parse to a host with a real TLD, set cr93c_active = false and cr93c_deactivation_reason. Both conditions must hold. List every deactivation in the report. Never delete rows.
0C. Load the IRS Texas extract once per run exactly as in v1.6 (https://www.irs.gov/pub/irs-soi/eo_tx.csv, local disk, line-level search only, SUBSECTION = 03 and STATUS = 01).
0D. Report the hygiene results, including any cr93c_website_url that appears on more than one row (possible duplicate organizations; do not delete).

PHASE A — Revisit queue (leads)
Selection: open leads (statecode = 0) that are still at lead_gcp_stage = 714000010, with lead_event_date between today and today + 180 days, where any of:
- lead_auction_evidence = Unverified (714000002) → always requeue.
- any auction column = Unclear (714000002) AND the event is within 120 days.
- a mission-critical field is blank AND the event is within 120 days. Mission-critical: the four auction columns, lead_event_date, companyname, subject, address1_line1, address1_city, address1_stateorprovince, address1_postalcode, firstname/lastname (a real contact), emailaddress1.
Never requeue a lead whose lead_date_search_notes starts with "FACEBOOK-ONLY" (the terminal state from Step 4).
Limits: skip any lead whose lead_last_enriched_on is within 21 days; skip any lead with lead_revisit_count ≥ 3; cap at 20, soonest events first.
Rules: free checks first (prior-year lookup is a read_query on lead and cr93c_scanfinding; contact and e-mail fallbacks are field logic; IRS lookup is a local file read), then re-crawl the event page, its ticket platform and its sponsorship page. UPDATE the existing lead, never create a second. Never overwrite Confirmed with Assumed. Never modify lead_event_id. Never touch lead_gcp_stage, lead_review_outcome, ownerid or parentaccountid: a human owns those. Set lead_last_enriched_on = today and lead_revisit_count = previous + 1 on every lead touched whether or not anything changed. Recompute the score and route after the update. Still blank after all that, leave blank; do not guess.

PHASE B — Scan new organizations
Step 1 — Build this run's batch
1A. SELECT TOP 50 cr93c_scansourceid, cr93c_name, cr93c_website_url, cr93c_last_scanned FROM cr93c_scansource WHERE cr93c_active = 1 ORDER BY cr93c_last_scanned ASC (nulls sort first), then cr93c_scan_priority ASC (blank sorts last), then cr93c_name. This matches the "Next scan batch" list in the Package Desk (Organizations → Scan list). Idempotency guard: exclude rows whose cr93c_last_scanned is already today; if a run fires twice in one day it must find its batch empty or partial and say so.
1B. Resolve a usable URL per org exactly as v1.6 (prefer the URL; the name only if it is a plausible domain; reject the junk list; one Firecrawl search if neither; still nothing → stamp cr93c_last_scanned and write a Screened Out finding with reason 8 "No working site"). Trust the URL, not the name; report Name/URL mismatches.
1C. Split the 50 across 5 workers of 10. Each worker runs Steps 2 to 7 independently. Budget 6 to 8 Firecrawl calls per org; if it runs out mid-Step-4 write Unclear and lead_auction_evidence = Unverified so Phase A picks it up.
1D. After each org set cr93c_last_scanned = today and cr93c_events_found. Batch these updates after the first 5 orgs and again at the end.

Step 2 — Crawl with Firecrawl: unchanged from v1.6 (homepage, /events, /calendar, /get-involved, /support-us, specific event links, PDF flyers with parsers ["pdf"], linked social when the site is thin).
Firecrawl + Apify together [UPDATED 2026-10-16]: Firecrawl reads the website, event pages, ticketing and registration platforms, sponsorship pages, PDF flyers and Candid. Apify reads Facebook, which Firecrawl cannot (see Step 4). Use both on the same organization whenever the site links to a Facebook page and the event, date or auction evidence is missing or thin on the site, or the organization's ACT history (cr93c_scan_notes / cr93c_scanfinding type 3) names a recurring event you cannot find on the site. Report Firecrawl and Apify call counts separately.

Step 3 — Keep only genuinely upcoming, live events: unchanged from v1.6. Confirmed past date → Missed Event finding (type 1). Cancelled/postponed → Screened Out reason 3. Past-year URL with no newer instance → Missed Event. No date anywhere after checking the event page, ticket platform, flyers and Facebook → Screened Out reason 4, with what you tried in cr93c_notes. Out of the Texas/Houston region → reason 9. PTA/PTO/political → reason 5. Politically charged cause → reason 6. Parse any visible date into lead_event_date (range → start date).

Step 3A — Retail and market formats: unchanged from v1.6, word for word. No inference may set an auction field; a Yes needs Confirmed evidence quoted from that event's own page; otherwise Screened Out reason 2 with the four auction fields No and the page text (or its absence) in cr93c_reason_detail. Kingwood Women's Club "28th Annual Holiday Marketplace" is the worked example that qualifies; "Empty Bowls presented by the Bulldog Marketplace" is the one that is not retail.

Step 4 — Exhaust Unclear before settling for it: unchanged order. (1) prior-year instance: SELECT on lead and cr93c_scanfinding by normalised organization and event name; (2) sponsorship, sponsor-packet and donation-request pages; (3) ticketing and registration platforms; (4) the prior-year page on the web. Only after all four may a field be Unclear.
Facebook pages [UPDATED 2026-10-16]: Firecrawl will not read facebook.com. When the org's event, date or auction evidence lives only on a public Facebook page or event, use the Apify connector: mcp__apify__call-actor with actor "apify/facebook-events-scraper", input {"startUrls": ["<facebook event URL or https://www.facebook.com/<page>/events>"], "maxEvents": 10} (startUrls are plain strings; the actor rejects {"url": ...} objects), callOptions {"maxTotalChargeUsd": 0.5}, then mcp__apify__get-dataset-items on the returned dataset. Public pages only, logged out; never pass cookies or log in. Text quoted from a Facebook event description counts as Confirmed evidence for that event (store the quote and the facebook URL in the snippet). Budget: at most 2 Apify calls per organization.
Facebook-only evidence (fallback): if Apify returns nothing usable, do not loop. For a new event: write it as a lead with the auction fields Unclear, lead_auction_evidence = Unverified, and lead_date_search_notes beginning "FACEBOOK-ONLY: <url>" so Phase A never requeues it; the reviewer e-mails the organizer from the Desk instead. For an existing lead reaching this state in Phase A: same note, and set lead_revisit_count = 3.

Golf tournament rule [ADDED 2026-10-16, owner decision]: about 90% of charity golf tournaments run a silent auction. When the event is a golf tournament (lead_venue Golf Tournament 714000002; golf classic, golf outing, scramble, invitational) and Step 4 leaves the silent auction Unclear, set lead_silent_auction = Yes with lead_auction_evidence = Assumed and lead_auction_evidence_snippet = "Assumed: golf tournament (GCP rule: ~90% include a silent auction)". Never apply it when the event's own page says there is no auction, never overwrite a Confirmed value, and never apply it to the other three auction columns. The event then scores and routes normally (it becomes a lead instead of being dropped at auction score 0). Clay shoots, sporting clays and other outdoor tournaments are not covered unless the owner extends the rule.

Step 5 — Extract the event: same fields as v1.6, written to the lead columns. Derive the real organization name from site content (companyname and lead_beneficiary_org). Address fallback order unchanged: organization website → Candid (one Firecrawl search, mandatory before declaring an address unavailable; fill lead_candid_url, lead_candid_note, lead_ein) → IRS Texas extract (Phase 0C file). Registry addresses never overwrite a website address. Set lead_address_source accordingly.

Step 5A — Classify venue, then infer silent auction: unchanged, including the tightened prior-year rule (match on organization AND normalised event name; only Silent Auction may be Assumed; never Online, Live or Raffle). Set lead_prior_year_auction on every lead, never blank. lead_auction_evidence is never blank; an Assumed Yes with a blank snippet is invalid → Unclear + Unverified.

Step 6 — Check what is new, or repair what exists: same logic against lead (open or not) instead of the Events table. URL match on lead_event_web_page (normalised; exactly one row and the URL appears nowhere else) → duplicate; otherwise companyname + subject (case-insensitive, trimmed, ignoring a leading year and the "[GCP] " prefix). Run the name match even when the URL matched. A duplicate with every mission-critical field filled and no Unclear → skip. Otherwise Phase A repair: fill ONLY blank fields, never modify lead_event_id, never overwrite Confirmed with Assumed, set lead_last_enriched_on = today. Missed events: same process against cr93c_scanfinding type 1. Before writing any Screened Out finding, check cr93c_scanfinding type 2 for the same organization + event. Keep the shared in-run log of (normalised org, normalised event, normalised URL) for the concurrent-write guard.

Step 6B — Research contacts: unchanged. Primary contact → firstname/lastname (split on the last space; if no contact, lastname = organization name), jobtitle, telephone1 (direct line else org main), emailaddress1 (theirs else org general), lead_contact_employee_or_volunteer. Second contact → lead_event_contact_2_name/email/phone, only if a different person. Org-level → emailaddress2, telephone2.

Step 7 — Write rows
Lead = subject "[GCP] " + event name, companyname, the Step 5/5A/6B fields, lead_event_id (24-char random string from a real random utility, fresh per row, never edited later), lead_event_date, lead_mail_by_date = event date − 21 days, lead_gcp_stage 714000010, lead_event_status 714000100, leadsourcecode 714000000, lead_source_of_event_information 714000120, lead_mailing_address_verified false, lead_last_synced_on = today, lead_last_enriched_on = today, lead_revisit_count 0, lead_event_score, lead_event_rating, lead_package_status and description = the score breakdown (one line per signal, as the old Score Breakdown formula did). Missed Event finding = whatever Step 5/5A fields you found, no contacts, cr93c_finding_type 1. Every finding also gets cr93c_event_id (fresh 24-char id) and cr93c_screened_on = today.

Step 7A — Qualification filter: PRE-WRITE CHECK immediately before each create_record on lead. Remove any record where (1) all four auction fields are a confident No → Screened Out reason 1, or (2) the event is a Step 3A retail format with no Confirmed Yes → Screened Out reason 2, or (3) the organization or event matches the Excluded or Sensitive word lists → reasons 5 or 6. Every Screened Out finding needs cr93c_screen_out_reason and, where the decision came from page text, a quote in cr93c_reason_detail. Applies to leads only; Missed Event findings are logged regardless.
